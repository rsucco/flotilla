# Flotilla

Turn-based naval strategy game (Battleship meets XCOM) on hex grids. Players buy a fleet with points; ships have weapons, special/secondary abilities, passives, and drawbacks.

**The README is the design spec.** Where code and README disagree on game rules, the README is correct and the code is a bug.

## Current State
- **Godot 4.7** project, Compatibility renderer (Web/mobile targets). Run/check it with `godot`.
- Headless parse check: `godot --headless --path . --check-only -s res://<file>.gd`
- After adding a `class_name` (or on a fresh checkout), run `godot --headless --path . --import` first. Headless runs don't rescan the class cache in `.godot/`, so the new type won't resolve.
- Code follows the global style rules, including call down, signal up (see Wiring below).
- Local hot-seat multiplayer only.

## Architecture
- **Board:** one 31x15 flat-top hex grid in odd-q offset coordinates, hexes as `Vector2i`. Columns 0-14 are player 0, 15 is no-man's-land, 16-30 are player 1 (`Grid.side_of()`, `Grid.columns_of()`). `Grid.get_hex_neighbor()` returns `Grid.OFF_GRID` for out of bounds, including column 15.
- **Rendering:** `Root._draw()` draws the whole board (hexes, hover, hit/miss markers, mines, labels), redrawn on every input event.
- **Turn loop:** `Root.play_game()` is a single coroutine: ship selection → placement per player → loop of (swap dialog → `new_turn()` → `get_move()`/`await made_move` until no ship has AP) until a fleet is empty. `Player` is the seam for every kind of player (hot-seat now; AI, LAN and online planned): a move is plain data, `(ship, action, target)`, checked by `Player.can_perform()` and carried out by `Player.perform()`. `LocalPlayer` only turns input into moves; whoever chose a move emits `made_move` once it's done. Setup works the same way: `Player.place_ships()` asks `_place(ship)` where each ship goes, within `Ship.can_place()`. Keep rules out of input handling, or other kinds of player can break them.
- **Modes:** `Root.mode` (static, set by the title screen) is hot-seat or vs-AI so far; LAN and online come later. Against the AI (`AIPlayer`, seat 1) there are no swap screens, `Root.viewer()` is always the local player, and the AI's turn plays out live: its ships are `Ship.cloaked` (hull and fittings unseen, aircraft shown) and `TurnReplay.watch()` masks its shots as a replay would. Tests that set `Root.mode` must put it back to `HOT_SEAT` in `after_each()`. The AI plays fair: it knows only what a player could (tile history on the other side, revealed copies, the opponent's fleet makeup, its own fleet), via `HeatMap`. Never let it read the opponent's ship positions; `test_only_what_a_player_could_know` guards this. Its numbers (ability worth, fades, fleets) are rough judgement to revisit after balance passes.
- **Combat resolution:** the *defending* `Player` resolves attacks in `receive_fire()` / `receive_special()` (matched on ability name). Ships override `hit()`, `fire()`, `use_special()`, `new_turn()` etc. for passives/drawbacks. `fire()`/`use_special()`/`use_secondary()` are coroutines that return when their animation is done (projectiles emit `done` on arrival, before the explosion); `perform()` awaits them, and the player can act again while explosions finish.
- **Turn replay:** `TurnReplay` (`turn_replay.gd`) records each attack and replays it for the defender after the hot-seat swap. Players emit `attack_started` (before the animation), `attack_landed` (just before `receive_*()`) and `attack_resolved`, plus `mine_blast` when one of their ships sets off a mine; Root connects these to the replay's `begin()`/`land()`/`end()`/`mine_blast()`. Playback uses ghost ships (`Ship.ghost`): fresh instances posed where the attacker fired from, which run the real `fire()`/`use_*()` animations while the recorded damage is shown as each attack lands. Ships sunk during the turn are kept (`Ship.held`) until the replay has shown them sinking. Anything in `fire()`/`use_*()` beyond animation (e.g. the battery revealing itself, the mine drop) must skip itself for ghosts.
- **Tile history:** each `Tile.history` entry is `[turn, "event string"]`. These strings are both the player-facing log and the data the renderer and the AI's `HeatMap` parse (e.g. `begins_with("Miss (")`) — changing wording changes behavior. A new event the AI should learn from needs a case in `HeatMap._read_history()`. Events about a known ship name it with `Ship.called()` ("Exeter (Destroyer)"): `title` is its own name (given in `Player.adopt()`), `ship_name` its type. Events that only betray a type (armour, sonar) give the type, and the heat map treats those as "one of them".
- **Navies:** each player commands one of `Navies.ALL` (`navies/navies.gd`: name, ensign `navies/<key>.svg`, ship name lists and prefixes, from Ryan's lists), chosen on the ship selection dialog; the opponent's is disabled there, and the AI takes any other. `Player.navy` is the key, `navy_name()` is what the game calls the player (swap screen, replay bar, victory, save slots). `Player.adopt()` names each ship from its navy's list, never twice in a fleet; batteries, and ships of players without a navy (tests), are numbered ("Coastal Battery II"). The navies are part of `Root.setup`, so saves and "Replay This Game" keep them.
- **`Grid.get_all_hex_neighbors(hex, n)`** returns endpoints of all n-step walks: n=1 excludes the center, n>=2 includes the center and duplicates. Callers dedupe manually.
- **Dice:** every roll the rules make (Fragile, armour, intercepts, where a mine hits) comes from `Dice` (`dice.gd`), never `randf()`/`pick_random()`, so a networked move replays identically from the host's seed. Visual randomness stays on the global generator. Tests of chance call `Dice.reseed(n)` beside `seed(n)`.
- **AP economy:** 4 AP default. Forward 1, rotate 2, reverse 4, fire/special/secondary 2 each; one fire charge per turn (carrier 2). Cooldowns start full and tick down at turn start.
- **Wiring (call down, signal up):** nothing below Root reaches up the tree. Root creates the grid and hands it down, sets each player's `opponent`, `effects` and `tile_history`, keeps the turn on `grid.turn` (which stamps `grid.log_event()` entries), and connects signals: GUI `action_pressed` → active player's `press()`, the top-left `Menu` button → pause menu; player `ship_shown`/`buttons_changed`/`fleet_changed` → GUI; player attack signals → `TurnReplay`. `Player.adopt(ship)` is the only way to add a ship: it sets the ship's `player`, `grid` and `effects` and connects `sank`/`mine_hit`. Ships add projectiles and effects with `spawn()`, which puts them in Root's `Effects` layer (above the ships) and gives projectiles the grid; projectiles add their particles with `add_sibling()`. Aircraft get `ship` from the ship that carries them. `LocalPlayer.active` is true from the start of its turn (after any replay) to its end. Keyboard and controller shortcuts (`LocalPlayer.SHORTCUTS`, input actions in `project.godot`) press the same HUD buttons through `press()`, and only while that button is enabled, so they can never do more than a click could. End Turn needs a one-second hold. The Esc menu opens on `action_menu` (Esc, Start); `ui_cancel` only ever goes back. HUD buttons don't take focus, or a clicked one would swallow Tab, Space and Enter. Over the board, `HexCursor` (arrow keys, left stick) stands in for the mouse by pushing the mouse motion a real mouse would; so read the pointer from mouse events (`Root.pointer`, `LocalPlayer.pointer_hex`), never `get_mouse_position()`, or the cursor won't move what you draw. A and Enter click at it (`LocalPlayer._click()`, and placement in `Ship._input`). Every menu and dialog gives a control the focus as it opens (`Focus.first()`, or `grab_focus(true)`), unshown so mouse players never see the ring; `ui_accept` (A, Enter, Space) presses it and `ui_cancel` (B, Esc) goes back. Give any new screen the same, or a controller can't use it, and hand the focus back when an overlay closes.
- **Saved games:** `SaveGame` (`save_game.gd`, static like `Settings`) keeps an autosave (written at every hand-off, or as each of the player's turns starts against the AI) and three slots (saved from the Esc menu, mid-turn only) in `user://saves`. `Root.save_state()` builds a save and `_restore()` puts one back; `SaveGame.ship_state()`/`restore_ship()` handle each ship. **Add any new per-ship state there too** (e.g. a new cooldown or counter), or it's lost on load. A save carries its `mode`, which Root takes from `Root.loaded`, so hot-seat and vs-AI games share the slots. A loaded hot-seat game opens at the swap screen; one against the AI goes straight into the player's turn. Bump `SaveGame.VERSION` whenever a save's contents change, so older saves read as empty instead of half-loading. The turn replay is saved too: `TurnReplay.save()`/`restore()` refer to ships by index into each fleet (afloat, then `held`), so give any new `TurnReplay.Action` field a place there. The title screen hands a save to Root through the static `Root.loaded`, as "Replay This Game" does with `Root.replay`. Tests and `shots.gd` point `SaveGame.dir` elsewhere (`test/pre_run.gd`) so they never touch the player's saves.
- **Text size:** `theme.tres` (project theme) sets the default font size to 13. Smaller text uses per-node `theme_override_font_sizes/font_size`.
- **Sound and settings:** music plays on the `Music` bus, effects on `Effects` (`default_bus_layout.tres`). Make every effect player with `Sfx.play()` or `Sfx.new_player()`, or the volume setting won't reach it. Quit with `Sfx.quit()`, not `get_tree().quit()`: it waits for stopped sounds to be freed, which otherwise leak at exit (the title screen routes the window's close button there too). `Settings` (`settings.gd`) is static and loaded once by the title screen, so running `root.tscn` directly plays at full volume. Don't add autoloads: `-s` scripts (`--check-only`, `shots.gd`) compile before autoloads exist, so any script referencing one fails there. The one exception is the Controller Icons addon's `ControllerIcons` (`addons/controller_icons`, for controller glyphs): at runtime it exists even under `-s` (GUT, `shots.gd`), but `--check-only` can't compile anything naming it. So our scripts never name `ControllerIcons` or `ControllerIconTexture`: load the texture's script by path (`GUI.GLYPH_SCRIPT`) or put the textures in scenes, and type them as `Texture2D`. The HUD shows each button's glyph only while a controller or a hotkey was the last thing used (`GUI.hints`).

## Godot Notes
- Aim with `direction_to(target).angle()`, and mind which way the sprite points (turrets up, missiles left, shells and torpedoes right).
- Engine callbacks (`_ready`, `_process`, `_input`) override the parent's; subclasses must call `super()`.
- Prefer `CPUParticles2D` (works everywhere). Its defaults: `local_coords` is false and gravity is (0, 980).
- `SceneTree.create_timer()` keeps running while the tree is paused unless you pass `process_always = false`. Game code passes `false` so effects freeze under the Esc menu.
- Controls block the mouse by default (`MOUSE_FILTER_STOP`). Set `MOUSE_FILTER_IGNORE` on overlays and effects (e.g. the nuke flash), or they eat clicks meant for the board.
- Create child nodes where they're attached (`_ready`, or the function that adds them), not as member defaults like `var p := AudioStreamPlayer2D.new()`. Instances that never attach them leak.
- Web exports use `variant/thread_support=false` so they run without COOP/COEP headers. Don't add threads.

## Testing
- GUT 9.7.1 (vendored in `addons/gut/`, configured by `.gutconfig.json`). Run all tests headless: `godot --headless --path . -s addons/gut/gut_cmdln.gd` (exits 1 on failure). Engine errors and `push_error` fail the running test. GUT skips a test script that fails to parse and still passes, so `test/post_run.gd` (the post-run hook) fails the run instead: if it reports "Could not load", fix that script.
- `test/unit/`: pure logic (`Grid`, `Tile`). `test/integration/`: rules exercised against an instantiated `root.tscn`.
- Files are `test_*.gd` and `extends GutTest`. Add a test for each README rule you implement or fix. Seed the RNG (`seed(n)`) in tests that depend on chance. Real controllers are ignored during a run (`test/pre_run.gd`), since Godot reads them even headless and one in use elsewhere would steer the game under test; push the tests' own joypad events through the viewport.
- `test/game_driver.gd` plays the real game through mouse input and button presses (`test_full_game.gd`, `test_gui.gd`). Hide `/root/GutRunner/GutLayer` in tests that click the board, or GUT's own window eats the clicks. The driver waits a frame before each click, as real input would.
- Run the suite after any game-logic change.
- Lint/format: `gdformat $(git ls-files '*.gd' | grep -v ^addons/)` then `gdlint` on the same files; both must be clean. Config is in `gdlintrc` (`max-public-methods` raised to 30 for `Ship`; split `Ship` up rather than raising it further).
- Visual checks: `test/screenshots/shots.gd` plays a scripted game in a window and saves screenshots of 16 states, to compare builds side by side. Usage is in the file's header. Run it, and any other script that needs real rendering, under `xvfb-run` as shown there, never in a visible window.
